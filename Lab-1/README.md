# Лабораторная работа 1. Удалённый файловый менеджер с имперсонацией клиента

RPC-сервер и RPC-клиент на C для Windows 10/11 (x64). Сервер даёт клиентам доступ к своим
файлам по UNC-путям: копирование файла на сервер, загрузку с сервера и удаление. Каждую
операцию сервер выполняет от имени клиента (имперсонация), поэтому доступ проверяет сама
Windows по правам (ACL) файла.

Подробно о том, какие функции и в каком порядке вызываются в каждом сценарии, написано в
[docs/how-it-works.md](docs/how-it-works.md).

## Структура проекта

```
Lab-1/
├── build.bat            сборка всего проекта
├── docs/how-it-works.md подробное описание работы кода по сценариям
├── src/                 исходный код
│   ├── idl/             интерфейс RPC
│   ├── common/          код, общий для сервера и клиента
│   ├── server/          сервер fm_server.exe
│   └── client/          клиент fm_client.exe
├── build/               (создаётся при сборке) сгенерированные MIDL файлы и .obj
└── bin/                 (создаётся при сборке) fm_server.exe, fm_client.exe
```

### src/idl/ — интерфейс

| Файл | Содержимое |
|---|---|
| `FileManager.idl` | Описание интерфейса на MIDL: UUID, версия, константы (`FM_MAX_CHUNK` = 1 МБ — размер блока передачи), тип контекстного дескриптора `FM_SESSION` и прототипы процедур: `FmLogin`, `FmLogout`, `FmWhoAmI`, `FmBeginUpload`, `FmWriteChunk`, `FmBeginDownload`, `FmReadChunk`, `FmCloseFile`, `FmDeleteFile` |
| `FileManager.acf` | Файл конфигурации приложения: `strict_context_handle` — сервер принимает контекстные дескрипторы только своего интерфейса |

По этим файлам MIDL генерирует в `build/gen/` заголовок `FileManager.h` и заглушки
`FileManager_s.c` (сервер) и `FileManager_c.c` (клиент).

### src/common/ — общий код

| Файл | Содержимое |
|---|---|
| `config.h` | Порт TCP по умолчанию (4747) и имя конечной точки ncalrpc |
| `console.h/.c` | `ConsoleInit` — переключение консоли в Unicode, чтобы кириллица выводилась корректно |
| `errors.h/.c` | `ErrorText` — текст системной ошибки по коду Win32/RPC |
| `midl_alloc.c` | `midl_user_allocate` / `midl_user_free` — функции выделения памяти, которые вызывают заглушки MIDL |

### src/server/ — сервер

| Файл | Содержимое |
|---|---|
| `main.c` | Точка входа: разбор аргумента (порт), запуск RPC, обработчик Ctrl+C |
| `rpc_server.h/.c` | Жизненный цикл RPC: `RpcServerUseProtseqEp` (ncacn_ip_tcp и ncalrpc), `RpcServerRegisterAuthInfo` (NTLM), `RpcServerRegisterIf2` с callback-проверкой безопасности (только шифрованные вызовы), `RpcServerInqBindings` + `RpcEpRegister`, `RpcServerListen`, остановка и снятие регистрации |
| `session.h/.c` | Сессия клиента (stateful): структура `SESSION` — токен пользователя, имя, адрес клиента, открытый файл передачи. Создание и уничтожение сессии, проверка дескриптора, имперсонация (`ImpersonateLoggedOnUser`) и возврат к правам процесса (`RevertToSelf`) |
| `handlers_session.c` | Процедуры интерфейса для сессии: `FmLogin` (проверка учётных данных через `LogonUserW`, создание сессии), `FmLogout`, `FmWhoAmI`, а также `FM_SESSION_rundown` — закрытие сессии, если клиент отключился без logout |
| `handlers_files.c` | Файловые процедуры интерфейса: загрузка на сервер, скачивание, закрытие передачи, удаление. Каждое обращение к файлу выполняется в имперсонированном потоке |
| `token_info.h/.c` | Описание токенов для журнала: пользователь, уровень целостности (Medium/High), уровень имперсонации. Отвечает на вопрос «от чьего имени работают процесс и поток» |
| `unc_path.h/.c` | `IsUncPath` — проверка, что путь имеет вид `\\server\share\...` |
| `log.h/.c` | Потокобезопасный журнал сервера с отметками времени |

### src/client/ — клиент

| Файл | Содержимое |
|---|---|
| `main.c` | Точка входа: разбор аргументов (адрес и порт сервера или `-lrpc`), запуск оболочки |
| `shell.h/.c` | Интерактивный цикл: приглашение `fm>`, таблица команд, проверка числа аргументов, справка |
| `connection.h/.c` | Подключение: `RpcStringBindingCompose` / `RpcBindingFromStringBinding`, настройка шифрования канала (`RpcBindingSetAuthInfoEx`), вызовы `FmLogin` / `FmLogout`, хранение контекстного дескриптора сессии |
| `commands.h` | Объявления всех команд клиента |
| `session_commands.c` | Команды `login` (в том числе скрытый ввод пароля), `logout`, `whoami` |
| `file_commands.c` | Команды `upload`, `download`, `delete`; передача файла блоками по 1 МБ с индикатором прогресса |
| `rpc_call.h` | Макрос `RPC_CALL` — вызов удалённой процедуры с перехватом исключений RPC (сервер недоступен, отказ в аутентификации) |
| `input.h/.c` | Чтение строки, скрытый ввод пароля, разбор строки на аргументы (поддерживаются пути в кавычках) |
| `output.h/.c` | Вывод ошибок и индикатора прогресса передачи |

## Сборка

Требуется Visual Studio 2022/2026 или Build Tools с компонентами «Разработка классических
приложений на C++» и Windows SDK (в нём есть компилятор MIDL).

```
build.bat
```

Скрипт сам находит Visual Studio, затем:
1. компилирует `src\idl\FileManager.idl` через MIDL → `build\gen\`;
2. компилирует заглушки и исходники из `src\common\`, `src\server\`, `src\client\` → `build\obj\`;
3. компонует `bin\fm_server.exe` и `bin\fm_client.exe` (библиотеки `rpcrt4.lib`, `advapi32.lib`).

Программы собираются со статическим CRT (`/MT`), поэтому на другую машину достаточно
скопировать exe-файл, Visual C++ Redistributable не нужен.

Для полной пересборки удалите каталоги `build\` и `bin\`.

## Работа с программой

### Подготовка машины-сервера (PowerShell от администратора)

Сервер обращается к файлам по UNC-пути, поэтому нужна общая папка. Права общего ресурса
открываем всем, а реальный доступ ограничиваем правами NTFS:

```powershell
New-Item -ItemType Directory C:\FMShare
New-SmbShare -Name fmshare -Path C:\FMShare -FullAccess ((New-Object Security.Principal.SecurityIdentifier 'S-1-1-0').Translate([Security.Principal.NTAccount]).Value)
```

Разрешить входящие подключения к серверу (нужно при подключении клиента с другой машины):

```powershell
New-NetFirewallRule -DisplayName "Lab-1 FileManager RPC" -Direction Inbound -Protocol TCP -LocalPort 4747 -Action Allow
```

### Запуск сервера

```
fm_server.exe [порт]
```

Порт по умолчанию — 4747. Сервер неинтерактивный: он только пишет журнал в консоль
(кто подключился, от чьего имени выполнена операция и с каким результатом).
Остановка — Ctrl+C.

От имени какой учётной записи запущен сервер, от той и работает его процесс. Чтобы
запустить сервер от другого пользователя:

```
runas /user:test2 "C:\путь\fm_server.exe"
```

### Запуск клиента

```
fm_client.exe <адрес сервера> [порт]     подключение по сети (ncacn_ip_tcp)
fm_client.exe -lrpc                      подключение к серверу на этой же машине (ncalrpc)
```

### Команды клиента

| Команда | Действие |
|---|---|
| `login <пользователь> [пароль]` | Вход под учётной записью машины-сервера. Можно указать `ДОМЕН\пользователь`. Если пароль не указан, он запрашивается без отображения на экране |
| `whoami` | Показать, от чьего имени работает процесс сервера и от чьего имени работает поток, обслуживающий клиента |
| `upload <локальный файл> <UNC>` | Скопировать файл с клиента на сервер |
| `download <UNC> <локальный файл>` | Загрузить файл с сервера на клиента |
| `delete <UNC>` | Удалить файл на сервере |
| `logout` | Завершить сеанс |
| `help` | Справка |
| `exit` | Выход (с автоматическим logout) |

Пути с пробелами заключайте в кавычки. UNC-путь указывает на общую папку сервера,
например `\\SERVER\fmshare\file.exe`, где `SERVER` — имя машины-сервера (`hostname`).

Пример сеанса:

```
fm_client.exe 192.168.56.10
fm> login test1
Пароль:
  Вход выполнен: test1
  Процесс сервера:              SERVER\Administrator [IL: High]
  Поток сервера (имперсонация): SERVER\test1 [IL: Medium, имперсонация: Impersonation]
fm:test1> upload big.exe \\SERVER\fmshare\big.exe
fm:test1> download \\SERVER\fmshare\big.exe copy.exe
  download: ошибка 5 - Отказано в доступе
fm:test1> logout
```

### Коды ошибок

| Код | Значение |
|---|---|
| 5 | Отказано в доступе: не хватает прав NTFS. Если код получен при `login` по сети — неверные учётные данные |
| 1326 | Неверное имя пользователя или пароль |
| 161 | Путь не в формате UNC |
| 1722 | Сервер RPC недоступен: сервер не запущен, неверный адрес или порт закрыт брандмауэром |
