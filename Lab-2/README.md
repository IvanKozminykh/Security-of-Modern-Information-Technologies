# Лабораторная работа 2. Служба Windows для резервного копирования в ZIP

Служба Windows `Lab2Backup` (C#, .NET Framework 4.x). Она следит за указанной директорией и
поддерживает ZIP-архив с резервной копией файлов, которые подходят под маски: новые файлы
добавляет в архив, изменённые заменяет. Подкаталоги любой вложенности сохраняются в архиве.
Все настройки задаются в конфигурационном файле, программа не интерактивная.

Тот же exe работает и как своя программа управления службой (SCP): устанавливает, удаляет,
запускает и останавливает службу из командной строки.

**Архивация.** Архив создаёт и обновляет класс `System.IO.Compression.ZipArchive`. Это
библиотека .NET Framework, она входит в состав Windows 10/11. Сторонние программы и библиотеки
архивации не используются.

**Работа со службой.** Без обёрток .NET (`ServiceBase`, `ServiceController`): функции SCM
вызываются напрямую из `advapi32.dll`, как в методичке:
`StartServiceCtrlDispatcher`, `RegisterServiceCtrlHandlerEx`, `SetServiceStatus`,
`OpenSCManager`, `CreateService`, `OpenService`, `StartService`, `ControlService`,
`QueryServiceStatusEx`, `DeleteService`.

## Структура проекта

```
Lab-2/
├── build.bat                  сборка
├── config/BackupService.ini   конфигурационный файл (при сборке копируется в bin\)
├── src/                       исходный код службы
├── demo/
│   ├── hello.cs               демо-программа (exe, который запускается из архива)
│   └── make-demo.ps1          создание тестовой исходной директории
└── bin/                       (создаётся при сборке) BackupService.exe, BackupService.ini, hello.exe
```

| Файл | Содержимое |
|---|---|
| `src/Program.cs` | Точка входа. Без аргументов процесс считает, что его запустил SCM, и переходит в режим службы. С аргументом выполняет команду SCP (`install`, `remove`, `start`, `stop`, ...) |
| `src/ServiceHost.cs` | Сервисное приложение: `StartServiceCtrlDispatcher` (связь с SCM), `ServiceMain` (точка входа службы), `ControlHandler` (обработка команд Stop, Pause, Continue, Interrogate, Shutdown), сообщение состояния через `SetServiceStatus` |
| `src/ServiceControl.cs` | SCP: установка (`CreateService` + описание через `ChangeServiceConfig2`), удаление (`DeleteService`), запуск (`StartService`), остановка (`ControlService(SERVICE_CONTROL_STOP)`), состояние (`QueryServiceStatusEx`), ожидание выхода из состояний `*_PENDING` |
| `src/NativeMethods.cs` | Объявления функций, структур и констант Win32 API |
| `src/BackupEngine.cs` | Резервное копирование: обход директории, сравнение с архивом, обновление ZIP, наблюдение за изменениями (`FileSystemWatcher`) |
| `src/Config.cs` | Чтение и проверка конфигурационного файла (в том числе проверка формата UNC) |
| `src/FileMasks.cs` | Сопоставление имён файлов с масками `*` и `?` |
| `src/Log.cs` | Журнал `BackupService.log` |

## Сборка

```
build.bat
```

Нужен только компилятор C# из .NET Framework 4.x (`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`).
Он есть в Windows 10/11, Visual Studio не нужна. Результат: `bin\BackupService.exe`,
`bin\hello.exe`, `bin\BackupService.ini`. Конфиг копируется в `bin\` только если его там ещё
нет, поэтому пересборка не затирает ваши правки.

## Команды

Команды `install`, `remove`, `start`, `stop`, `restart` выполняются **в командной строке от
имени администратора**.

| Команда | Действие |
|---|---|
| `BackupService.exe install` | Установить службу (тип запуска: вручную, учётная запись: LocalSystem) |
| `BackupService.exe start` | Запустить службу и дождаться состояния «Выполняется» |
| `BackupService.exe stop` | Остановить службу и дождаться состояния «Остановлена» |
| `BackupService.exe restart` | Перезапустить службу |
| `BackupService.exe status` | Состояние службы, PID процесса, пути к конфигу и журналу |
| `BackupService.exe remove` | Удалить службу. Работающая служба сначала останавливается |
| `BackupService.exe check` | Проверить конфиг и показать, какие файлы попадут в архив (`[+]`), а какие нет (`[-]`) |
| `BackupService.exe run` | Выполнять резервное копирование прямо в консоли, без службы (для отладки, Ctrl+C — выход) |

Из оснастки «Службы» (`services.msc`) служба тоже управляется: Запустить, Остановить,
Приостановить, Продолжить, Перезапустить. Все действия пишутся в журнал `bin\BackupService.log`.

## Конфигурационный файл

Файл `BackupService.ini` лежит рядом с `BackupService.exe`. Служба читает его при запуске,
поэтому после правки службу нужно перезапустить.

```ini
[Backup]
SourceDir    = \\localhost\C$\BackupDemo\source   ; откуда копировать (вместе с подкаталогами)
ArchiveDir   = \\localhost\C$\BackupDemo\backup   ; где лежит архив (создаётся автоматически)
ArchiveName  = backup.zip                         ; имя архива
ScanInterval = 10                                 ; период полной проверки, секунд

[Masks]
*.docx
*.exe
file?.txt
important.txt
```

- Пути задаются в формате UNC (`\\сервер\общий_ресурс\путь`). Служба работает под LocalSystem,
  ей доступен административный ресурс `\\localhost\C$`. Можно использовать и свою общую папку.
- В секции `[Masks]` по одной маске или имени файла в строке. `*` — любое количество любых
  символов, `?` — ровно один символ. Регистр не важен. Маска без `\` сравнивается с именем файла
  в любом подкаталоге. Маска с `\` сравнивается с путём относительно `SourceDir`, например
  `folder1\*.txt`.
- Если в конфиге ошибка, служба не запустится. `start` и оснастка покажут код ошибки службы 1,
  причина будет записана в журнал.

## Как это работает

1. **Запуск.** `ServiceMain` регистрирует обработчик команд, сообщает SCM состояние
   `START_PENDING`, читает конфиг и сообщает `RUNNING`. Затем в этом же потоке работает цикл
   резервного копирования.
2. **Проверка.** Каждая проверка обходит `SourceDir`, отбирает файлы по маскам и сравнивает
   их с содержимым архива по размеру и времени изменения. Новые файлы добавляются в архив,
   изменённые заменяются: старый элемент удаляется, новый записывается
   (`ZipArchiveMode.Update`). Путь файла внутри архива повторяет вложенность папок:
   `folder1/folder2/folder3/file3.txt`. Удалённые из источника файлы остаются в архиве, ведь
   это резервная копия.
3. **Когда проверка запускается.** Сразу после изменений в директории (уведомления
   `FileSystemWatcher`, пауза 1,5 с, чтобы файл успел дописаться). Кроме того, раз в
   `ScanInterval` секунд на случай пропущенных уведомлений.
4. **Архив открывается только на время обновления.** Это доли секунды, в остальное время
   архив свободен, и его можно открыть проводником, не останавливая службу. Если архив или
   файл в этот момент занят другим процессом, проверка повторяется через 3 секунды.
5. **Stop / Shutdown.** Обработчик сообщает `STOP_PENDING` и подаёт сигнал циклу. Пока
   дописывается текущее обновление архива, раз в секунду увеличивается `dwCheckPoint`. После
   выхода из цикла служба сообщает `STOPPED`. **Pause / Continue** приостанавливают и
   возобновляют наблюдение. После Continue сразу выполняется проверка, чтобы учесть изменения
   за время паузы.

## Сценарий демонстрации

Все команды выполняются в **cmd от имени администратора** из каталога `Lab-2\bin` (после `build.bat`).

**1. Установка службы**
1. Откройте `services.msc` и покажите, что службы «Lab-2 Backup Service» в списке нет.
2. Выполните `BackupService.exe install`.
3. Обновите оснастку (F5). Служба «Lab-2 Backup Service» появилась, тип запуска «Вручную».

**2. Конфигурация и исходная директория**
1. Откройте `notepad BackupService.ini` и покажите `SourceDir`, `ArchiveDir`/`ArchiveName` и маски.
2. Создайте исходную директорию. Можно скриптом:
   ```
   powershell -ExecutionPolicy Bypass -File ..\demo\make-demo.ps1
   ```
   Он создаст `C:\BackupDemo\source\folder1\folder2\folder3`. В каждой папке будут
   `reportN.docx`, `appN.exe` (копия `hello.exe`), `fileN.txt` и `notesN.txt`, в корне ещё
   `important.txt` и `file10.txt`. Можно создать и вручную: тогда exe-файлы скопируйте из
   `bin\hello.exe`.
3. Выполните `BackupService.exe check`, чтобы показать, что под маски попадают `*.docx`,
   `*.exe`, `fileN.txt` и `important.txt`, а `notesN.txt` и `file10.txt` не попадают
   (`?` — ровно один символ).

**3. Запуск:** `BackupService.exe start`.

**4. Работа архиватора**
1. В `C:\BackupDemo\backup` появился `backup.zip`. Откройте его и пройдите по папкам
   folder1 → folder2 → folder3.
2. Отредактируйте и сохраните, например, `folder1\folder2\file2.txt`.
3. Добавьте новый файл, например `folder1\folder2\folder3\file9.txt`.
4. Откройте архив заново. В нём новая версия `file2.txt` и новый `file9.txt` на своём месте.
   Чтобы показать, что архив **обновился, а не создан новый**:
   - в каталоге по-прежнему один `backup.zip`, и в его свойствах дата «Создан» не изменилась;
   - в журнале `type BackupService.log` видны строки `заменён : folder1/folder2/file2.txt`,
     `добавлен: folder1/folder2/folder3/file9.txt`, `Архив обновлён: добавлено 1, заменено 1`.

**5. Работа с архивом без остановки службы**
1. Служба работает (`BackupService.exe status`). Откройте `backup.zip` двойным щелчком во
   встроенном просмотрщике проводника.
2. Запустите `folder1\folder2\folder3\app3.exe` двойным щелчком. Если проводник спросит про
   сжатую папку, нажмите «Выполнить». Откроется окно «Программа запущена из резервной копии»
   с путём к файлу: проводник извлёк его во временную папку.

**6. Остановка и удаление**
1. В `services.msc` нажмите «Остановить» для «Lab-2 Backup Service».
2. Выполните `BackupService.exe remove`.
3. Обновите оснастку (F5): службы больше нет. Пока оснастка держит открытой страницу
   свойств службы, Windows только помечает службу для удаления. В этом случае закройте
   свойства или саму оснастку и откройте её снова.

## Контрольные вопросы

**1. Какие операции выполняются при установке сервиса в систему?**
Программа установки открывает SCM с правом `SC_MANAGER_CREATE_SERVICE` (`OpenSCManager`) и
вызывает `CreateService`. В вызове передаются имя службы, отображаемое имя, тип
(`SERVICE_WIN32_OWN_PROCESS`), тип запуска (`SERVICE_DEMAND_START`), реакция на ошибку
запуска, путь к exe, учётная запись (NULL — LocalSystem), а также при необходимости группа
загрузки и зависимости. SCM добавляет службу в свою базу и создаёт раздел реестра
`HKLM\SYSTEM\CurrentControlSet\Services\Lab2Backup` с параметрами `ImagePath`, `Type`,
`Start`, `ErrorControl`, `ObjectName`, `DisplayName`. Описание задаётся отдельно через
`ChangeServiceConfig2` (параметр `Description`). Служба после этого ещё не запущена: её
запускают через `StartService`.

**2. Что такое SCP и зачем необходимо его реализовывать?**
SCP (Service Control Program) — программа, которая управляет службами через функции SCM:
`OpenSCManager`, `CreateService`, `OpenService`, `StartService`, `ControlService`,
`QueryServiceStatusEx`, `DeleteService`. Стандартные SCP — это оснастка «Службы» и `sc.exe`.
Свой SCP нужен, чтобы приложение само могло установиться в систему и удалиться из неё,
запускаться и останавливаться из командной строки или скриптов без сторонних утилит, а также
с нужными параметрами. Сервисное приложение не может само себя зарегистрировать: регистрацию
выполняет SCM по запросу SCP.

**3. Какие возможности по управлению сервисами НЕ предоставляет оснастка «Службы»?**
- Установка (создание) и удаление служб: это делается через `CreateService`/`DeleteService`
  (свой SCP или `sc create` / `sc delete`).
- Изменение пути к исполняемому файлу, типа службы и имени службы.
- Изменение зависимостей (оснастка их только показывает) и группы загрузки.
- Передача службе пользовательских команд (коды 128–255, `sc control`).
- Настройка дескриптора безопасности службы, то есть кто может её запускать и останавливать
  (`sc sdset`).
- Запуск по событиям-триггерам (`sc triggerinfo`), SID службы, обязательные привилегии
  (`sc privs`).
- Управление службами драйверов: оснастка показывает только службы Win32.
